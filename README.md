# Versionize + Gitea Docker build

This repository contains a Gitea Actions setup for building the
`Granch.RTServerCore` Docker image with a version generated by Versionize.
Versionize runs in a separate `dotnet10` job. The `dind` job only receives the
resolved version and release commit SHA, then builds and pushes the Docker
image.

## Required Gitea secrets

- `GITEA_TOKEN` - token with permission to clone the repository and push release
  commits/tags.
- `REGISTRY_PASSWORD` - password for `gitea.granch.local:3000` Docker registry.

## Commit message format

Versionize is configured in `.versionize` to parse commit headers like:

```text
[feat] add new endpoint
[fix] (rtserver): handle reconnect
[perf!] improve hot path
```

The `Granch.RTServerCore` project uses tags in the format:

```text
Granch.RTServerCore-v1.2.3
```

On the first Versionize release, `1.0.0` is expected. Later releases are bumped
from matching commit messages since the latest `Granch.RTServerCore-v*` tag:
`[fix]` creates a patch release, `[feat]` creates a minor release, and `[type!]`
creates a major release.

`build-docker-image.sh` reads the version from the `VERSION` environment
variable set by the workflow. If it is not set, the script falls back to the
latest `Granch.RTServerCore-v*` git tag.
